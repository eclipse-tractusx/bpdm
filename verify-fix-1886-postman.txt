Result
The fresh manual test on 2026-11-04 confirmed the correct address types
after Pool synchronization:
- Address X is SiteMainAddress for Site A.
- The same address X is AdditionalAddress for Site B.

Restart Gate with the updated code.
Pool, Gate, Orchestrator and cleaning-service-dummy must be running.
Use the required authorization if security is enabled.

Postman assertions
Paste into Scripts -> Post-response (or Tests) for the Step 4 request:

pm.test("Output search succeeds", () => {
    pm.response.to.have.status(200);
});

const outputs = pm.response.json().content;
const a = outputs.find(x => x.externalId === "fix-1886-site-a-01");
const b = outputs.find(x => x.externalId === "fix-1886-site-b-additional-01");

pm.test("Both requested outputs exist", () => {
    pm.expect(outputs).to.have.lengthOf(2);
    pm.expect(a).to.be.an("object");
    pm.expect(b).to.be.an("object");
});

pm.test("X is Site A's main address", () => {
    pm.expect(a.site.siteBpn).to.eql("BPNS0000000002V9");
    pm.expect(a.address.addressBpn).to.eql("BPNA00000000056F");
    pm.expect(a.address.addressType).to.eql("SiteMainAddress");
});

pm.test("X is an additional address of Site B", () => {
    pm.expect(b.site.siteBpn).to.eql("BPNS0000000003UK");
    pm.expect(b.address.addressBpn).to.eql("BPNA00000000056F");
    pm.expect(b.address.addressType).to.eql("AdditionalAddress");
});

pm.test("Pool membership has synchronized into both outputs", () => {
    pm.expect(a.additionalSites.map(x => x.siteBpn))
        .to.include("BPNS0000000003UK");
    pm.expect(b.additionalSites.map(x => x.siteBpn))
        .to.include("BPNS0000000002V9");
    pm.expect(a.address.updatedAt).to.eql(b.address.updatedAt);
});

Conclusion
The original reproduction returned SiteMainAddress for the output following
Site B, even though Site B had a different main address.
The fresh test with the fix returned AdditionalAddress for Site B while
preserving SiteMainAddress for Site A after Pool synchronization.
This confirms the fix for the reported scenario.
